# Multi-Threaded BFS for CSR-Formatted Graphs

## Requirements

- GCC supporting OpenMP
- Make
- CSR-formatted binaries

## Build

```bash
make
```

Then an executable `graph_BFS.bin` will be generated in the same directory. 
## Usage

```bash
export OMP_NUM_THREADS=<number of threads>
./graph_BFS.bin </path/to/binary/beg> </path/to/binary/csr> <source>
```

where the first two parameters are binary `beg` and `csr` files, and `source` is the identifier of the starting point which should be a `long`. 

For example:

```bash
export OMP_NUM_THREADS=4
./graph_BFS.bin ./graph_data/toy.dat_beg_pos.bin ./graph_data/toy.dat_csr.bin 3
```

This will conduct a parallel BFS with 4 threads on `toy.dat` starting from vertex `3`.

Then the max level and the corresponding vertex identifier will be output in the terminal. In addition, the time reading and traversing the graph will also be output separately.

## Comments

- For a classical BFS task, a weight list is not needed, but the code is easy to extend to be a SSSP by including a weight list and a vector storing and updating distances from the source.

- We always traverse the whole graph, so it's unnecessary to specify a target, but it's easy to modify the code for this.

- Our implementation has been tested on `com-orkut.ungraph.txt` and `toy.dat`, where the binary files were generated by `tuple_text_to_binary_csr_mem` in the same repository. 

- For `com-orkut.ungraph.txt`, speedups of 2 and 4 threads are up to 1.4x and 1.8x respectively on Intel Core i7-6700HQ. 

- Only `toy.dat` and its binary files are included in `./graph_data` considering space.
